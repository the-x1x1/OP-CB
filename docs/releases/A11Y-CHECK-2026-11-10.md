# Accessibility check of the renderer, automated part (2026-11-10)

The roadmap's accessibility audit is a walk by hand: a screen reader (NVDA or Narrator)
through the main tasks, keyboard-only use of the map, and the HUD's ink over the imagery in
each visual style. This is the part a headless browser can do, run in the build container on
the renderer's demo build (recorded data, no globe: Cesium and MapLibre are stubbed there), at
1920×1200. It does not replace the walk.

## What was checked, on every screen below

- Every visible control (`button`, link, `input`, `select`, `textarea`, `role=button|tab|switch|checkbox|menuitem|slider`,
  focusable `tabindex`) has an accessible name: `aria-label`, `aria-labelledby`, a `label`,
  its text, an image's alt text or a `title`.
- Every visible `img` has an `alt`.
- Every `aria-labelledby`, `aria-describedby` and `aria-controls` names an element that exists.
- No `id` is used twice.
- A Tab walk (25–45 stops): each stop draws a visible focus (outline or the focus ring's
  box-shadow).

Screens: the start screen; the main view; each of the eight lens groups opened in the lens
rail; the Command Center's Online, Offline, Overview, World & Maps, Knowledge, Local
Intelligence, Communications, Preparedness and Resources sections; the menu.

## Found and fixed (feature/after-0.7.4)

- **`aria-controls` named elements that were not there** (16 on the main view): the search
  box's results list while closed, the menu button's popover while closed, each lens group's
  expand button while the group is closed, and every unselected tab of a tab strip (only the
  selected panel is rendered). Each now names its target only while it is rendered
  (`packages/ui` Search, Popover, Tabs; `layer-panel.tsx`), with tests in `packages/ui/src/ui.test.ts`.
  Re-run: none left on any screen above.

## Found and left

- Nothing else. No unnamed control, no image without alt text, no duplicate id. In
  Preparedness, the Tab walk reports one stop without a ring: a later part (day or year) of
  the expiry date field, which Chromium focuses inside the field; the field itself shows the
  app's ring. To look at by eye on the installed build.

## Still for the walk by hand

A screen reader's announcements (names are present; what is said, in what order, is not
checked here); the globe and 2D map by keyboard (the stubbed map cannot be driven here); the
HUD's contrast over imagery in each style; dialogs opened from the menu (Settings, Sources).
